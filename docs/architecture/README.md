# 아키텍처 메모리

이 폴더는 `AGENTS.md`처럼 저장소 전체의 작업 규칙을 강제하는 곳이 아니라, 기능을 구현하거나 변경할 때 먼저 읽어야 할
아키텍처 맥락과 외부 시스템 계약을 보존하는 곳이다.

## 읽는 순서

1. 작업 대상과 관련된 문서를 이 폴더에서 찾는다.
2. 문서의 **확정 계약**, **구현 방향**, **미결정 사항**을 구분해서 읽는다.
3. 실제 코드와 문서가 다르면 임의로 한쪽을 맞추지 말고 원본 계약과 변경 이력을 확인한다.
4. 계약이 바뀌면 구현과 테스트뿐 아니라 이 폴더의 관련 문서도 함께 갱신한다.

## 문서 목록

- [AI-백엔드 노드 이벤트 계약](ai-backend-node-event-contract.md): AI 서버가 Redis Stream으로 노드 생성·수정 명령을
  전달하고 백엔드가 멱등하게 처리하는 구조
- [백엔드→AI 노드 명령 처리 결과 계약](ai-command-result-contract.md): 백엔드가 처리한 노드 명령의 성공·실패를
  별도 Redis Stream으로 통지하는 계약(AI 서버 소비자 관점)
- [회의 상태 수신과 AI 맥락 전달 계약](meeting-ai-context-contract.md): Recall 봇 상태 웹훅으로 회의 상태를 반영하고,
  녹음 시작 시 회의 이벤트를 발행해 AI 서버가 내부 API로 회의 노드의 하위 그래프를 조회하는 경로

## 현재 시스템 맥락

- 운영 코드는 `com.aideep.domain.<domain>` 중심으로 구성한다.
- 인증과 워크스페이스 도메인은 구현되어 있고, 노드 도메인은 Redis 이벤트 소비, DB 반영 및 기존 실시간 서버로의 이벤트 버스 발행까지 구현되어 있다. 노드 REST API는
  아직 없다.
- PostgreSQL은 JPA로 접근하며 운영 스키마 자동 변경은 사용하지 않는다.
- Redis 연결과 Spring Data Redis 의존성은 이미 존재한다. 현재 Redis는 인증 데이터 저장에도 사용된다.
- 도메인 간 협력은 상대 도메인의 엔티티나 저장소를 직접 참조하지 않고 서비스 또는 명시적인 인터페이스와 DTO를 경계로 한다.

## 문서 갱신 규칙

- 외부 계약에서 그대로 가져온 값은 **확정 계약**에 기록한다.
- 코드 구조나 장애 처리 방식처럼 저장소에 맞춰 정한 내용은 **구현 방향**에 기록한다.
- 원본에서 정하지 않았거나 팀 합의가 필요한 값은 **미결정 사항**에 남긴다.
- 구현이 완료되면 관련 클래스, 설정 키, 마이그레이션, 테스트 위치를 문서에 연결한다.
